# 《晧哥說》專欄寫作與發布指南

本 Skill 規範「環策晧脈（moenv-policy-pulse）」網站專欄 **《晧哥說》** 的選題查證、語氣人設、文章結構、Frontmatter 格式、排版細節與發布驗證流程。

---

## 一、檔案位置與命名規範

- **存放目錄**：`04_晧哥說/`
- **參考範本**：`04_晧哥說/_template_draft.md`
- **選題雷達**：`04_晧哥說/00_待把脈候選雷達.md`
- **檔名規則**：
  - **絕對不可**以 `_` 或 `00_` 開頭（網站載入器 `web/src/lib/data.ts` 會自動略過底線與 `00_` 開頭檔案）。
  - 建議格式：`<YYYY-MM-DD>_haoge-<english-slug>-<YYYYMMDD>.md` 或 `<YYYY-MM-DD>-<english-slug>.md`（使用英文短橫線 slug 可避免網址出現冗長 URL 編碼；發布後請勿隨意更動已上線檔名，以免破壞外部連結）。

---

## 二、Frontmatter 欄位規範

必須嚴格符合 `web/src/content.config.ts` 的 Zod schema 定義：

```yaml
---
title: "文章標題（建議 15～30 字，具觀點張力與對比感）"
date: 2026-11-22
status: draft          # draft（草稿，網站不顯示）| published（正式上線）
summary: "一句話點出政策核心訊號或評論立場，約 40～85 字。"
topics:
  - "主議題"           # topics[0] 會決定 HaoTalkCover.astro 的封面主色調與幾何構圖
  - "次議題"
related_news:
  - "14527"            # 填入環境部新聞 news_id 或 newsno（字串形式），網站自動串連新聞卡片
timeline_slug: ""      # 選填：對應 05_政策脈絡線/ 的 slug，留空或省略皆可
cover: ""              # 選填：自訂圖片路徑（如 "/images/hao-talks/example.png"），留空則自動生成雜誌封面
---
```

### 欄位注意事項
1. **`status`**：撰稿與審閱期間務必維持 `draft`；只有經使用者確認定稿要發布時，才改為 `published`。
2. **`topics`**：建議 2～4 個繁體中文標籤。**`topics[0]` 應優先填寫最具代表性的主議題**（如 `空氣品質`、`碳費徵收`、`淨零轉型`、`水資源永續`、`資源循環`、`PFAS`、`綠色算力`），因為網站封面元件 `HaoTalkCover.astro` 會依 `topics[0]` 與標題雜湊自動生成雜誌封面。
3. **`related_news`**：撰寫前務必從 `資料/moenv_news_index.jsonl` 或 `04_晧哥說/00_待把脈候選雷達.md` 核對正確的新聞編號（`news_id`），不可憑記憶編造。
4. **`timeline_slug`**：若文章對應既有政策脈絡線，請從 `05_政策脈絡線/` 現有檔案中選用對應 slug（目前包含：`air-quality`、`carbon-fee`、`international-cop`、`pfas-control`、`resource-circulation`、`water-pollution-fee`）。

## 三、語氣、視角與寫作風格

《晧哥說》的定位是「政策把脈者與實務觀察家」，不是新聞稿複誦機，也不是純粹的情緒批判。

### 核心語氣原則
- **冷靜犀利、有溫度的對話感**：以第一手觀察者的口吻與讀者對話，常用句式如：「這裡不替政策打分數，但有兩件事值得多看一層」、「我想追問的是……」、「表面上只是例行展延，但拉開時間軸來看……」、「不能只當口號」。
- **拉開時間軸、看穿制度設計**：不只看單一公告，而是回溯過去的預告、上路、修正節點，找出「雙軌機制」、「外部成本內部化」、「配套缺口」或「污染轉移風險」。
- **數據與名詞精準**：只引用新聞原文、開放資料或經查證的公開統計數據（如 `13 萬輛`、`13.5%`、`24/7 全時綠電`、`CCPI 2027`）。
- **對比金句收尾**：善用短句與對比結構總結洞見，例如：
  - 「真正的循環，是把問題解掉，不是把問題轉手。」
  - 「車輛電動化要向前走，電力低碳化也得跟上。」
  - 「綠色算力不只比晶片，也得把綠電供應、能源效率與實際減碳一起算清楚。」
- **語言規範**：一律使用臺灣繁體中文慣用語；專有名詞如 `PFAS`、`CCPI`、`COP31`、`AI` 維持英文大寫。

## 四、文章結構（依題材深度二選一）

### 模式 A：深度把脈型（約 400～800 字，適用法規修正、制度變革）
可參考 `04_晧哥說/_template_draft.md` 與已發布深度長評，於開頭附上對應新聞導引，並以四個層次展開：

```markdown
> **對應新聞**：[環境部新聞標題](https://enews.moenv.gov.tw/moenv-news/zh-tw/News/XXXXX)（YYYY-MM-DD）

## 一、看門道（一句話破題）
用 1～2 句點出這項政策或新聞真正值得關注的核心訊號。

## 二、追脈絡（前世今生）
拉開時間軸，回顧預告、上路、修正等關鍵節點與累計數據（可內嵌超連結連回歷史新聞）。

## 三、晧哥把脈與把關（實務衝擊與盲點）
拆解制度背後的設計邏輯、對產業／民眾的實質影響，以及容易被忽略的風險或配套缺口。

## 四、給企業與讀者的行動提醒
提供具體、可執行的準備方向、申報／比價管道或後續觀察指標。
```

> **提示**：網站內文頁 `<header>` 已會自動渲染 `title` 作為 `<h1>`，因此內文可視需要直接從 `> **對應新聞**：` 或正文開始，避免雙重主標題重複（若為了 Obsidian 單獨閱讀方便保留 `# 標題` 亦可，兩者皆相容）。

### 模式 B：短評快筆型（約 200～400 字，適用論壇發言、國際評比、單點趨勢）
參考 `2026-11-08`～`2026-11-16` 風格，不強加四段 `##` 小標，改以 **4～5 個精煉短段落** 推進，每段 1～3 句：
1. **破題現象**：點出新聞事件或官方說法。
2. **關鍵追問**：提出核心疑問或對照數據。
3. **實務盲點**：指出執行面、能源鏈或後端風險的真實考驗。
4. **金句收斂**：用一句有記憶點的短句收尾。

### 參考資料區塊（有引用外部來源時必附）
當文章引用了環境部新聞以外的數據、報告或媒體報導時，文末必須附上 `## 參考資料`，格式統一為：

```markdown
## 參考資料

- YYYY-MM-DD｜[資料標題（若為查閱日請註明：查閱日期）](https://example.com/...)
```

## 五、寫作與發布工作流程

1. **挑題與查證**：
   - 查看 `04_晧哥說/00_待把脈候選雷達.md` 或近期新聞，確認目標新聞的 `news_id`、發布日期、發布單位與摘要（可查 `資料/moenv_news_index.jsonl`）。
   - 若引用外部數據（如經濟部統計、IEA 報告、法規條文），務必核實來源日期與 URL。
2. **建立草稿**：
   - 在 `04_晧哥說/` 建立新 `.md` 檔案，初始先設 `status: draft`。
   - 填妥 Frontmatter 並完成正文與 `## 參考資料`。
3. **本機建置與驗證**：
   - 確認 `status` 改為 `published`（若要驗證公開頁面）後，於 `web/` 目錄執行建置測試：
     ```powershell
     $env:ASTRO_TELEMETRY_DISABLED="1"; npm --prefix web run build
     ```
   - 確認建置成功無 Zod schema 錯誤、無漏鏈或異常警告。
4. **自動發布上線（使用者確認「可以發布」後自動接續執行）**：
   - 只要使用者明確表示「可以發布」，在完成 `status: published` 與 `astro build` 驗證通過後，**自動執行**以下 Git 發布步驟（無需再次詢問是否 push）：
     1. 執行 `git status` 與安全檢查，確認只暫存本次新增／修改的文章（與必要設定檔），絕不納入 `_local/`、`99_內部工作區/`、`local-mail.env`、`key.env` 等私有檔案。
     2. 執行 `git add <本次文章與相關檔案>`、`git commit -m "feat(hao-talks): publish <文章標題或slug>"` 與 `git push origin main`。
     3. 回報 commit hash 與已推送至 `main`，Cloudflare Pages 將自動建置上線。
